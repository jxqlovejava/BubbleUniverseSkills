# 抖音录屏贴纸视频模板

复刻竞品爆款形态：**左上角固定手写便利贴贴纸 + 产品洗牌→抽牌→解牌全流程录屏**，输出 9:16 抖音成片。

## 一条命令

**自动录屏（推荐，主题参数化）：**

```bash
python3 auto_record.py "他对我是不是真心的"              # 全流程自动走查+录屏+合成
python3 auto_record.py "主题" --copy sahuang            # 换贴纸文案
python3 auto_record.py "主题" --no-compose              # 只录屏不合成
python3 auto_record.py "主题" --cover                   # 顺手出一张首图并拼到片头（耗即梦积分）
```

**首图/封面（`gen_cover.py`，可独立用）：**

```bash
python3 gen_cover.py                  # 温暖治愈带淡淡忧郁电影感女性人像 9:16，出 3 张挑一张 → out/
python3 gen_cover.py --count 1        # 只出 1 张；--seed N 固定形象配方可复现；--dry-run 只看提示词
python3 gen_video.py raw/xxx.mov --cover out/cover-xxx.png   # 已有首图手动拼片头（--cover-dur 调秒数）
```

- **拼片头 0.8s**：`auto_record.py --cover` 全自动（即梦出图 → `gen_video.py --cover` 拼到成片最前面）；抖音选封面/首帧直接是这张人像。**封面也叠贴纸**——钩子文案是信息流点击理由。贴纸首图与录屏段**同一位置**（默认左上 60,200 头顶留白区；`--cover-sticker-x/y` 默认跟随 `--x/--y`，要分开调才显式传），0.8s 过渡时贴纸不跳变。空白段复检映射已减掉首图偏移，不会误剪

- **人物形象每次随机变化**：脸型/发型/妆容/服饰四个槽位池随机采样（`yuanyan-nuanzong-meigui-yamai` 这类配方 key 打在文件名里可回溯），风格帧（左后暖金逆光轮廓光 + 暖棕奶金背景 + 低饱和偏暖 + 梦幻柔雾，温柔眼神带淡淡忧郁）保持不变——每条视频换一张脸，账号内容不同质化
- 提示词骨架 = jimeng-image 示例13 分段编号式 + 预设G 肤质/负向块；改池子改 `gen_cover.py` 顶部四个 dict

**手动录屏：**

```bash
python3 gen_sticker.py --copy pianbuguo      # 1. 出贴纸 PNG（content.json 选文案）
./record_sim.sh                              # 2. 模拟器录屏（走完洗牌→抽牌→解牌，回车停）
python3 gen_video.py raw/<时间戳>.mov        # 3. 合成 1080×1920 成片 → out/
```

## 自动录屏（auto_record.py）

零依赖原生方案：`simctl screenshot` + macOS Vision OCR 带框定位 → CGEvent 真实点击；中文输入走 `simctl pbcopy` 写设备剪贴板 + 点编辑菜单「粘贴」。
（唯一非系统库：定位发送按钮用 Pillow 扫像素，`pip install pillow`，本机已装。）

> **中文只能走剪贴板**：模拟器收到 CGEvent 键盘事件后只按 keycode 翻译，**丢掉事件里带的 Unicode 载荷**——所以不管 JXA 还是 Swift 直输，中文都会整段变成 `aaaa…`（服务端会判「无实质内容的无效输入」）。别再试直输。
> 顺带：`simctl pbcopy` 写的是**设备剪贴板**，本机剪贴板（`pbcopy`）可有可无。

- **唯一依赖**：终端 App 授予「辅助功能」权限（系统设置 → 隐私与安全性）。脚本启动自检，缺失会弹授权框
- **前置**：模拟器已 boot、App 已装、**已手动登录一次**（预检查 `flutter.isLoggedIn`，未登录直接报错退出）、账号有剩余解读次数
- **自动开「连接硬件键盘」**：preflight 用 ⌘⇧K 打开（Simulator 菜单 I/O → Keyboard）。关着的话点输入框弹不出「粘贴」编辑菜单，主题永远上不了屏；开着还顺带让点输入框不弹软件键盘，成片更干净
- **主题上屏反馈**：发送按钮是无字紫色圆钮，**有字才由灰转紫**——脚本按颜色定位圆心并用它当「已上屏」判据（固定比例会因输入行漂移落空，实测差 150px+），同时用它点发送
- **素材归档**：每次运行自动建 `out/<问题名>/`，里面只放**这一篇的发布文案 + 成片**（公共文件如贴纸 PNG、校准文件仍在 `out/` 根）
- **流程**：冷启动 → 首页点「开始占卜」→ 提问页粘贴主题 → 发送 → 等「开始抽牌」→ 洗牌「结束洗牌」→ 扇形抽牌（首次自动校准中牌坐标，存 `out/.calibration.json`）→ 「查看解读」→ 等解读页（主题标题或正文占位任一命中）→ 等正文落地 → 再录 12s 收尾
- **等正文落地的正确标记**：正文占位 `正在为你解读塔罗牌…` 消失 = markdown 正文渲染出来了。**别等输入框那条 `塔罗牌解读进行中…`**——那是输入框 hint，正文出来后还要十几秒才变，等它就等于把整段正文拖进加速段（成片里解读一闪而过）
- **成片自动剪辑**：洗牌页首次出现时打**挂钟时间戳**，但合成前必须校准成**视频时间**——`simctl recordVideo` 起录到首帧有固定 offset，录制时间轴比挂钟慢（这条录屏 18s，另一条 4s，逐条不同）。校准方法 `find_page_start()`：整片解码 + fps 取样定位洗牌页首帧（**不能**用 `-ss T -i` 探针，关键帧稀疏会返回十几秒前的内容——踩过，成片直接从抽牌开始），然后用这个漂移量修正所有加速打点。**起点 = 定位时间 +0.3s**：fps 取样就近取帧，定位点可能比洗牌首帧早 ~0.5s，直接当起点会把上一页（连接宇宙能量 loading）的尾巴带进成片；+0.3s 只损失洗牌开头 0.12s（2.5x 下）。首页/提问/牌阵不进成片；默认 **2.5x 变速**（`--speed` 可调）
- **剪掉空白死时间（`--drop-blank`，默认开）**：App 在抽牌之间会连续白屏 1-5 秒（见下面「已知 App 侧问题」），录屏里这段是纯死时间。判据是**两步**：亮度初筛（均值 >228 且标准差 <42）+ **OCR 确认「整页无文字」**（排除状态栏时钟，y>140 才算）——只用亮度在变帧率录屏上不稳（同一段两次 fps 采样结果能对不上，实测漏掉过整段白屏）；App 白屏的硬特征是「没有任何文字」，这一步才是可靠的。扫描范围用 `--drop-range` 限定在「抽牌页→解读页」之间，避免误剪开头的洗牌页淡入（它也是亮且平的 228/40）。成片若仍有残留，会映射回原片**密扫确认**后再重剪（成片判据会误报抽牌页，不确认就剪会把正常画面剪掉——21.3s 被剪成 14.5s 那次就是）
- **尾部常速段（`--tail-hold 7.5`）**：解读段按常速播才看得清；**从视频真实末帧倒推**而不是用打点的挂钟秒——recordVideo 是变帧率，成片时间轴比挂钟慢十几秒，末尾还可能没有可解码帧，用挂钟时间裁会把解读整段吃掉。数值给到 7.5 而非 3：变帧率裁段实际产出只有名义值一半左右（6.0 名义 → 3.0s 可见）
- **分段加速**：抽牌等待段再快 2 倍（总 5x）；解读 loading 段是静止页，再快 6 倍（总 15x）。`--boost SS:TO:F[,SS:TO:F…]` 支持多段，自动录制按打点带
- **画幅（`--fit`，默认只出 `bleed`）**：设备屏 1320×2868 比 9:16 更长，铺满必然要裁掉 521px
  - `bleed` 裁上下铺满，零侧边：顶裁 315（状态栏 + 「无限畅享占卜」页眉，解读页标题 y=375 保住）+ 底裁 206（牌堆下缘，「结束洗牌」按钮 y=2596-2652 整颗保住）。代价：解读正文流到 y>2662 的行会被切
  - `bars`（备用，日常不出）保留整屏，两侧缺口用画面自身最外两列像素横向拉伸补齐
  - `pad`/`both` 老方案，已弃用
- 好评/订阅弹窗自动关；解读次数不足会明确报错

**故障表：**

| 现象 | 原因与处理 |
|------|-----------|
| 点击全部落空 | Simulator 窗口未聚焦/被遮挡；脚本已 activate，仍失败则手动点一下模拟器窗口 |
| 输入框点不到、粘贴失败 | Dock 遮住窗口底部死区 → 脚本启动自动 Window→Fit Screen 缩放窗口；改过 Dock 设置后重跑即可 |
| 弹「想从 CoreSimulatorBridge 粘贴」 | iOS 粘贴隐私弹窗，脚本会自动点「允许粘贴」；想永久免弹：模拟器 设置 → 塔罗气泡 → 从其他 App 粘贴 → 允许 |
| 多台模拟器同时 booted | 脚本自动选「装了塔罗气泡的那台」（按 UDID + 窗口标题匹配），不用手动关其他设备 |
| 抽牌页探测点全不中 | 删 `out/.calibration.json` 重校准；仍失败看 `out/_fail-*.png` 截图。校准含牌点+确定按钮坐标，之后抽牌走盲点零 OCR（牌间间隔 ~1s） |
| 抽到第 N 张就抽不动 | 扇形是真实牌堆，抽过的位置留缺口，盲点固定在同一处必落空 → 每抽一张前随机左右滑一下扇形（`swipe_fan`）。连续 14 轮（牌位 10）还没到结果页才报错 |
| 主题没上屏（发送按钮不亮） | 模拟器「连接硬件键盘」没开（脚本会自动开，失败会提示手动开）；或 `simctl pbcopy` 没写进去。**别改成 CGEvent 直输**：模拟器丢 Unicode，只会打出一串 a |
| 发送点击没反应 | 发送按钮位置随输入行漂移，别用固定比例；脚本按颜色找圆心。`_fail` 截图里按钮若是灰的（0.2 透明度）说明主题压根没上屏 |
| 服务端判「无实质内容的无效输入」 | 主题多半被输错（历史原因：直输成 `aaaa…`）或本身就是感想式短句，换个具体问句重跑 |
| 成片里解读一闪而过 / 看不到 | 等错了标记（等成输入框 hint）或尾部裁剪用了挂钟秒 → 见上面「等正文落地」「尾部常速段」两条 |
| 卡与卡之间闪空白帧 | **App 侧白屏**（不是合成问题），见下面「已知 App 侧问题」；合成端 `--drop-blank` 已自动剪掉 |
| 两侧黑边太粗 | 用 `--fit bleed`（默认，裁上下铺满零侧边）；`--fit bars` 是备用；`--side-color` 调兜底色 |
| 提示未登录 | 模拟器里手动登录一次（见下），登录态持久化（检查 `flutter.loginToken`） |

**已知 App 侧问题：确认牌后 2-2.5s 空屏**（2026-09-13 定位到根因）

- 现象：点「确定」→ 翻牌(0.8s) → 停 1s 看牌 → **接着 2-2.5s 屏幕上只剩一张正在缩小的牌，其余全空**（3 张牌阵约 0.7-1s，10 张牌阵 2.0-2.5s，随渲染负载变）→ 才回到扇形抽牌页。每抽一张都来一遍。
- 根因：`controllers/animation_controller.dart:208 confirmCardSelection()` 第三步 `isDialogBackgroundTransparent = true` 的**原意是「让弹窗背景变透明，好看见卡牌飞进卡位」**，但唯一读这个标记的地方（`widgets/card_selection_dialog.dart:182`）**只把卡名/按钮透明掉，没动背景**；而弹窗根容器（同文件 `:192`）永远铺着一整屏不透明的 `QuestionGradientUtil.currentGradientDecoration` → 整屏只剩那张缩小的牌 = 空屏。
- 修法（未实施，等决策）：把 `:192` 的 `decoration` 在标记为真时置空即可（弹窗与抽牌页用的是**同一个**渐变，露出来视觉无缝；被选中的牌在扇形里本来就被隐藏，不会重复）。

`gen_video.py` 常用参数：`--copy <key>` 换文案（自动重渲染贴纸）、`--ss/--to` 掐头去尾（trim 滤镜实现，帧精确——`-ss` 输入搜寻在 simctl 录屏上关键帧稀疏会漂 2s+）、`--boost SS:TO:F[,SS:TO:F…]` 指定 raw 区间额外加速（抽牌等待段 2x、解读 loading 段 6x，自动录制按打点带上）、`--fit bleed|bars|both|pad` 画幅适配、`--tail-hold N` 尾部 N 秒常速（解读段，按真实末帧倒推）、`--crop-top/--crop-bottom` bleed 裁切量、`--side-color` 兜底色、`--x/--y` 调贴纸位置、`--sticker-width` 调贴纸大小、`--opacity` 调不透明度（默认 0.82，下层文字可透出）。

## 贴纸拆解（复刻依据）

| 维度 | 结论 |
|------|------|
| 形式 | 米色奶油底（#F3E8C8）撕纸便利贴、微旋转 2-3°、黑色手写体（HanziPen SC）两行短句、软阴影 |
| 位置 | 全程固定左上、头顶上方留白区（默认 60,200；首图与录屏段同位。封面人脸实测上沿 y≥500，贴纸占 y200-442 不压脸；人物位置即梦每张会漂，中部任何固定位置都会中招，只能放头顶）+ 半透明（0.82），下层内容可透出 → 水印级记忆点 |
| 文案公式 | 上句立冲突（挑衅/炫耀）+ 下句归因产品（因为我会看牌），第一人称口语，7+7 字 |
| 心理钩子 | 炫耀引评论，把看透人心的能力嫁接到产品；观众看到最后验证真假 → 拉完播 |
| 分工 | 贴纸讲故事立人设，录屏证明产品真实存在 |

文案变体库在 `content.json`（key 即 `--copy` 参数）。铁律：不用「」引号。

**发布文案结构**（`gen_caption`）：标题行 → 品牌软植入句（单独一行）→ 过程行 → 标签行。软植入句由 `tarot-mass-divination/scripts/opener.py` 按话题 AI 生成、失败回退固定池——**全项目唯一实现，微信聊天双拼 / 解读截图 / 自然照片 / 情侣四宫格四个图文模板共用**（本模板单独拷出去找不到 skill 时走同款内联池，保住零依赖）。2026-09-16 用户拍板统一到这个结构。

**发布文案禁词**（`gen_caption`）：`塔罗`/`占卜`/`算命`/`卜卦` 一律不出现，话题标签也跟着换成情感向（`#情感 #恋爱 #心理 #情绪价值 #关系 #成长`）。唯一豁免是品牌名 `塔罗气泡App`（用户 2026-09-11 拍板照写）——`--selftest` 里对文案和 `content.json` 全部贴纸文案都做了断言，加新文案时把禁词带回来会直接自检失败。`牌`/`抽牌`/`解读` 不在禁词内。

## 首次准备（模拟器）

1. 装 Rosetta：`softwareupdate --install-rosetta --agree-to-license`（Podfile 排除了模拟器 arm64，需 x86_64 构建）
2. 跑 App：`cd ~/Documents/workspace/TarotBubble && flutter run -d "iPhone 16 Pro Max"`
3. 登录：模拟器不支持一键登录，会自动跳**短信验证码登录**（login_manager.dart 降级逻辑）

5. 模拟器 I/O → Keyboard → **Connect Hardware Keyboard 打勾**（脚本会自动开；手工开一次后常驻）
6. 首次粘贴会弹「允许粘贴」；想永久免弹：模拟器 设置 → 塔罗气泡 → 从其他 App 粘贴 → 允许
